# Routing

`/` immediately navigates to the locale configured by `content/site.json` (`defaultLocale`), which is also supplied to Astro’s i18n configuration. Astro’s automatic default-locale redirect is disabled; the root route owns an inline head redirect with a meta-refresh fallback so a generated “redirecting” document is not shown during normal navigation. The localized areas are `/{locale}/` for the portfolio, `/{locale}/projects/` for the project index and case studies, and `/{locale}/blog/` for editorial articles. Blog category archives use `/{locale}/blog/category/{category...}/`; article URLs preserve their content folders under `/{locale}/blog/{folder...}/{slug}/`.

Journey, projects, contact, and résumé are homepage sections at `#journey`, `#projects`, `#contact`, and `#resume`. The Projects index is also a localized route. A visible project receives `/{locale}/projects/{id}/` only when its canonical record has a bilingual case study. Hidden review and backlog records generate no route. The homepage progress navigator is rendered only on the homepage and follows Home → About → Skills → Focus → Experience → Projects → Journey → Contact → Blog.

Blog landing copy is authored at `content/blog/{locale}/_index.mdx`. Blog articles are locale-prefixed in source. General topic articles may retain category folders such as `content/blog/en/devops/docker/article.mdx`. Every visible portfolio project has a published `content/blog/{locale}/projects/{project-id}/overview.mdx` in both locales; this is the project’s canonical rich mother document and project cards link to it. Additional files under the same project folder become child articles automatically. Use `npm run content:new -- blog <locale> projects/<project-id> <article-slug>` to create a supplemental draft with matching `category`, `subcategory`, and `slug` frontmatter. Draft articles are filtered before static paths are generated.

The static fallback is `src/pages/404.astro`, with explicit localized variants at `/en/404/` and `/fa/404/`. It provides a localized return-home action and browser-history fallback while preserving the shared header, theme, typography, and footer.
