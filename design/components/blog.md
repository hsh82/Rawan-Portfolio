# Blog

Articles use the Astro Content Layer from `content/blog`. Each logical entity has one `entry.json` plus `en.mdx` and `fa.mdx` siblings. The landing entity is `content/blog/landing/`; project overviews and child articles live below `content/blog/projects/<project-id>/`. The loader emits stable locale-prefixed collection IDs, so the blog index, category archives, and articles remain nested below `/{locale}/blog/` without changing public URLs. The blog has no section progress navigator. The listing derives categories, tags, favorite project hubs, and recent articles from metadata. The reader adds navigation, Table of Contents, Mermaid, Markmap, and print styles.

Project articles live in `content/blog/projects/<project-id>/articles/<article-slug>/` with one shared `entry.json` and two localized bodies. Every project hub owns sibling `entry.json`, `en.mdx`, and `fa.mdx` overview files with matching `category: projects` and `subcategory: <project-id>`; its homepage, Projects-index card, and Blog favorite hub link directly to the stable `/overview/` reading route. The overview renders its derived child-article list. Use `npm run content:new -- blog projects/<project-id> <article-slug>` for supplementary bilingual drafts. `npm run content:migrate-bilingual` migrates legacy locale-first documents, and `npm run content:migrate-project-hubs -- --dry-run` plans the final registry/overview-to-hub move. Article links, translations, RSS, canonical URLs, project breadcrumbs, and project-scoped previous/next navigation are generated from normalized collection IDs.

Blog cards and readers may use the shared `image` and registered `icon` metadata. Local images use `media/...` references and are resolved through the public media mirror; HTTPS images are retained as remote references. `imageAlt` is read from the current locale’s shared metadata, and cards fall back from image to icon to the existing card treatment without changing their fixed aspect ratio.
